## Difficulté 1 — Playwright ne trouve pas ses librairies sur NixOS

### Symptôme
```
ImportError: libstdc++.so.6: cannot open shared object file
[...] libglib-2.0.so.0: cannot open shared object file
```

Playwright installe son propre Chromium bundlé (via `playwright install`),
mais ce binaire attend des librairies système dans `/usr/lib` — chemin
inexistant sur NixOS où tout est dans `/nix/store`.

### Solution
Utiliser le Chromium système fourni par Nix (`pkgs.chromium`) en passant
son chemin explicitement à `p.chromium.launch()` :

```python
browser = p.chromium.launch(
    headless=True,
    executable_path="/run/current-system/sw/bin/chromium",
    args=["--no-sandbox", "--disable-setuid-sandbox"],
)
```

Et pour le venv Python :
```bash
LD_LIBRARY_PATH=/nix/store/.../gcc-15.2.0-lib/lib /tmp/pw-venv/bin/python script.py
```

Le `shell.nix` de System C encode cette solution de façon reproductible :
```nix
export PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1
export PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH="${pkgs.chromium}/bin/chromium"
```

## Difficulté 2 — Jobboom retourne des offres sponsorisées, pas les résultats de recherche

### Symptôme
L'URL `/fr/emploi/_lfr?q=infirmière&l=Quebec` charge avec `networkidle` et
renvoie 15 offres d'emploi en HTML — mais aucune n'est une infirmière.
Ce sont toujours les mêmes offres sponsorisées (RONA, Penske, Nortera),
quelle que soit la requête. La page affiche pourtant « 2634 résultats ».

### Diagnostic
Jobboom utilise deux URL paths distincts :
- `_lfr` — affiche les offres sponsorisées du moment, indépendamment
  du paramètre `?q=`. Les résultats filtrés par le mot-clé sont censés
  être rendus par le JS de Vue.js, mais ce rendu ne se déclenche pas
  en mode headless (aucune requête XHR supplémentaire interceptée).
- `_lfrk` — l'URL réelle des résultats de recherche filtrés, construite
  par le JS lors de la soumission du formulaire.

Ce path `_lfrk` n'est pas documenté et n'apparaît jamais dans les liens
statiques de la page — il est généré dynamiquement.

### Solution
Simuler l'interaction utilisateur : charger `_lfr`, remplir le champ
`input[name='keyword']`, appuyer sur Entrée, attendre la navigation :

```python
page.goto("https://www.jobboom.com/fr/emploi/_lfr", ...)
kw = page.query_selector("input[name='keyword']")
kw.fill(terme)
kw.press("Enter")
page.wait_for_load_state("networkidle", ...)
# → navigue vers /fr/emploi/{slug}/_lfrk?dk={terme}
```

Cette navigation produit l'URL correcte et les offres correspondant
réellement au terme recherché.

## Difficulté 3 — Les pages d'offres Jobboom affichent une modale en H1

### Symptôme
`page.text_content("h1")` retourne `"Voulez-vous vraiment quitter ce processus?"`.
Le titre réel du poste apparaît en deuxième H1.

### Cause
La page d'offre Jobboom intègre une modale de confirmation de sortie
(pour les candidats en cours de postulation). Cette modale est dans le DOM
mais invisible visuellement. Son H1 précède le H1 du poste.

### Solution
Utiliser le sélecteur spécifique du titre Jobboom :

```python
for sel in [".jobDescHeaderTitle", "h1[data-test-id='job-title']"]:
    el = page.query_selector(sel)
    if el:
        titre = el.text_content().strip()
        break
```

Fallback : parcourir toutes les H1 et ignorer celle qui contient « quitter ».

## Difficulté 5 — Perte de données Jobillico (31301, 64100)

### Ce qui s'est passé
En milieu de session, un `rm -f system-c/data/raw-comparaison/offres/*.json`
a été exécuté pour nettoyer une première passe ratée. Ce `rm` a aussi
effacé les données Jobillico pour les CNP 31301 (infirmière, 2 offres) et
64100 (vendeur, 2 offres), qui existaient depuis la session précédente.

Les CNP 12200, 21222, 72300 n'ont pas été recréés dans la même session
(codes différents), donc leurs fichiers ont survécu.

### État actuel
- **31301** : données Jobillico perdues. IDs connus : 16194985 (Multi Options
  Nursing), 17204914 (CHSLD Côté-Jardins). Récupération possible si les
  offres sont encore actives.
- **64100** : données Jobillico perdues. IDs connus : 17323190 (Latulippe),
  17332109 (RONA). Même situation.
- **12200** : Jobillico avait retourné 0 offre (recherche hors-cible —
  le site référençait des contrôleurs financiers, pas des techniciens
  comptables).

### Leçon
Ne jamais `rm -f *.json` dans un répertoire de données actif sans vérifier
si des fichiers préexistants ont une valeur irremplaçable. Préférer
`ls -la` + suppression ciblée par CNP.

## Note sur generate_json.py

Ce script est un **seed one-shot**, pas un pipeline dynamique. Il hardcode
les textes NOC/Guichet-Emplois/IMT comme littéraux Python et les sérialise
en JSON. Le chemin de sortie est figé vers `/tmp/opencode/…` (non portable).
Il a servi à créer les fichiers `taches/` manuellement, une seule fois.
Il n'est pas conçu pour être relancé ou maintenu.
