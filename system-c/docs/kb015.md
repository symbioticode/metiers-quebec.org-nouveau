# KB015 — Phase 3 : matrice CNP×appellations, cnp_check(), audit

## Objectif

Construire la référence officielle des appellations d'emplois liées aux 5 CNP cibles (31301, 72300, 21222, 64100, 12200) à partir de qualificationsquebec.com, puis valider tous les fichiers existants contre cette référence.

## Ce qui a été produit

| Fichier | Rôle |
|---|---|
| `data/reference/cnp-appellations-officielles.json` | Matrice complète : 516 CNP codes, 5 avec autres appellations complètes |
| `scripts/cnp_check.py` | Fonction `cnp_check(cnp, terme, matrice)` → valide/partielle/aucune |
| `scripts/test_cnp_check.py` | 20 tests unitaires (unittest), tous passent |
| `scripts/scrape_qualifications.py` | Script de extraction via l'API AJAX de qualificationsquebec.com |
| `scripts/audit_cnp.py` | Audit des fichiers taches/ et offres/ contre la matrice |
| `data/raw-comparaison/audit-cnp.md` | Résultat : 19 vérifications, 5 échecs attendus |

## Difficultés rencontrées

### 1. Pagination de qualificationsquebec.com ne fonctionne pas via URL

**Problème** : Les 46 pages de résultats utilisaient le paramètre `tx_solr[page]` dans l'URL, mais le serveur renvoyait toujours la même page 1 (12 résultats identiques). La pagination est entièrement JavaScript côté client.

**Solution** : En inspectant le JavaScript (`professions.js`), j'ai découvert l'endpoint AJAX POST `/ajax/professions` qui accepte `limit=600&pg=1` — permettant de récupérer les 550 professions en un seul appel.

```python
data = "limit=600&pg=1".encode()
req = urllib.request.Request(AJAX_URL, data=data, headers={
    "Content-Type": "application/x-www-form-urlencoded",
    "X-Requested-With": "XMLHttpRequest",
}, method="POST")
```

### 2. Extraction des autres appellations nécessite des requêtes individuelles

**Problème** : Les 550 professions n'ont que le titre principal sur la page de recherche. Les « Autres appellations d'emplois » sont sur chaque page individuelle (`/profession/{slug}/`).

**Solution** : Pour les 5 CNP cibles uniquement, requête individuelle sur chaque page profession avec regex sur la section `<ul>` suivant « Autres appellations d'emplois ». Les slugs n'étaient pas connus d'avance — il fallait les extraire de la recherche.

### 3. Slash dans les titres français (masculin/féminin)

**Problème** : Les appellations comme « mécanicien/mécanicienne en plomberie » posent problème pour le matching par sous-chaîne. « mécanicien en plomberie » n'est PAS une sous-chaîne de « mécanicien/mécanicienne en plomberie » à cause du `/`.

**Solution** : Logique de split par `/` avec expansion du contexte partagé :
- « mécanicien/mécanicienne en plomberie » → variants : ["mécanicien en plomberie", "mécanicienne en plomberie"]
- Le regex capture le pattern `prefix/suffix context` et reconstruit chaque variante complète.

### 4.noc.esdc.gc.ca bloqué

**Problème** : Le site officiel ESDC refusait toutes les requêtes webfetch (erreur transport).

**Solution** : Utilisation de `www23.statcan.gc.ca/imdb/p3VD_f.pl` — même contenu NOC 2021, source StatCan. Fonctionnel mais à noter comme dépendance secondaire.

### 5. emploisdecadres.com inaccessible

**Problème** : Toutes les requêtes webfetch renvoyaient 404 (protection Cloudflare/bot detection). Jobboom.com utilise du JavaScript pur — les pages search ne retournent pas de contenu HTML utilisable.

**Solution** : Documentation de l'échec dans les fichiers JSON et `rapport.md`. Ces sources sont inaccessibles sans headless browser.

## Fichiers existants analysés

### `data/raw-comparaison/generate_json.py`
Script qui génère les fichiers `taches/*.json` à partir de données hardcodées. Contient les文本es bruts extraits de IMT en ligne, Guichet-Emplois et NOC/OASIS pour les 5 CNP. Ce n'est PAS un scraper — c'est un fichier de données mises en forme JSON.

### `data/raw-comparaison/generate_table.py`
Script qui génère `table-comparaison.md` en lisant `taches/*.json` et `offres/*.json`, disposant le texte verbatim dans un tableau par métier et par source. Gère les deux formats de fichiers offres (format-A jobillico et format-B jobboom/emploisdecadres). Déjà opérationnel.

### `data/raw-comparaison/table-comparaison.md`
Fichier généré (516 lignes) — table de comparaison brute avec sections par métier, colonnes NOC/Guichet-Emplois/IMT/Jobillico/Jobboom/Emploisdecadres, et colonne Notes vide.

## Résultat de l'audit

- **19 vérifications** au total
- **6 correspondances exactes** : les `nom_metier` qui matchent exactement une appellation Q2
- **8 partielles** : les `nom_metier` ou titres d'offres qui matchent par sous-chaîne
- **5 échecs** : tous attendus — variation naturelle des titres d'employeurs (ex. « Vendeur - Conseiller(ère) à la vente » au lieu de l'appellation officielle)

Les 5 échecs ne sont pas des erreurs mais reflètent la réalité : les titres d'emplois sur les sites de recrutement divergent des appellations officielles.

## Correctifs adversariaux (commit `b5bacd3`)

Un test exhaustif de backtest (265 740 paires CNP × terme) a identifié 5 bugs critiques, corrigés un par un. Après chaque fix, `test_cnp_check.py` est relancé — 20/20 OK.

### Fix 1 : chaîne vide / espaces / None

**Bug** : `"" in x` est toujours `True` en Python → `cnp_check("72300", "")` validait.

**Correction** : garde explicite en début de `cnp_check()` — `None`, `str` non-String, ou chaîne vidée/après strip → retour `aucune` immédiat.

### Fix 2 : entrée bare « infirmier/infirmière » retirée de 31301

**Bug** : « infirmière auxiliaire » validait sous 31301 (infirmier autorisé) grâce à l'entrée générique `infirmier/infirmière` dans `autres_appellations`. Or 32101 (infirmier auxiliaire) existe dans la matrice.

**Correction** : l'entrée bare `infirmier/infirmière` retirée de 31301 (125 → 124 autres appellations). Scan complet : les autres entrées bare (plombier/plombière, libraire, etc.) sont sans conflit.

### Fix 3 : frontières de mots `_contains_as_phrase()`

**Bug** : la sous-chaîne `"Chefs"` matchait 5 autres CNPs non-liés (chefs religieux, chefs d'orchestre, etc.) — 49 faux positifs au total.

**Correction** : `re.search(r"(?<!\w)needle(?!\w)", haystack)` remplace `needle in haystack`. Sweep complet : 26 collisions résiduelles, toutes des chevauchements légitimes du système CNP (ex: « Architectes » dans 21200/21201, « Ingénieurs » dans 10+ sous-cat).

### Fix 4 : singularize naïf `_singularize_naive()`

**Bug** : « Infirmière auxiliaire » (singulier) ne matchait pas « Infirmières auxiliaires » (pluriel officiel 32101).

**Correction** : strip du dernier `s` ou `x` de chaque mot. La matrice est singularisée côté appelation aussi (haystack) pour que les deux côtés soient comparables.

### Fix 5 : `html.unescape()` dans le scraper

**Bug** : les titres de qualificationsquebec.com contenaient parfois des entités HTML (`d&rsquo;` au lieu de `d'`).

**Correction** : `html_module.unescape()` ajouté dans `scrape_qualifications.py` après chaque extraction texte. Matrice régénérée — 0 entité HTML résiduelle. (Préventif : la matrice actuelle était déjà propre.)

- **0 entité HTML** dans la matrice
